## 1. Summary

G16 activated 81 Eventbrite sources and reported `duplicates = 0` while the
database's duplicated native event IDs grew **47 → 197 → 239**. G16 root-caused
the cause and left it unfixed, because the fix belongs to the production
`conexao-event-runtime` plugin.

**G17 fixes it.** The public visibility rule is unchanged. The importer gains a
narrow, explicit, token-guarded reconciliation path that can see
`source_not_found` records, so a reappearing event is **restored** instead of
being inserted a second time.

| Measure | Before | After |
|---|---|---|
| Reappearance creates a 2nd native record | **yes** (two IDs, e.g. `[14243, 14244]`) | **no (exactly one ID)** |
| Regression suite (non-WP-CLI) | 40 passed / **17 failed** | **57 passed / 0 failed** |

## 2. Root cause

### 2.1 The exact query path

| Step | Location | What happens |
|---|---|---|
| 1. Identity lookup | `class-event-deduplicator.php` `find()` → `find_by_source()` | resolves the existing event by `_event_source` + `_event_source_id` via `WP_Query` |
| 2. Query arguments | same | `post_type=event`, `fields=ids`, `meta_query` = AND(`_event_source`, `_event_source_id`) |
| 3. Interception | `conexao-event-runtime.php` `filter_public_event_queries()` on `pre_get_posts` | matches `post_type=event` and injects the `_event_status = published OR NOT EXISTS` clause |
| 4. Removal | same | a `source_not_found` row does not satisfy the clause and is dropped from the result |
| 5. Consequence | `class-event-importer.php` `upsert_event()` | `$post_id` is `0`, so the create/update/restore branch (line 1488) is unreachable and `wp_insert_post()` runs → **duplicate** |

The restore logic at `class-event-importer.php:1488` is **correct and was never
reached**. The public filter is also **correct**. The defect is that an
importer-internal query was subject to a public visibility boundary.

### 2.2 Why the existing suite did not catch it

`test-reappearing-event-lifecycle.php:156` asserted
`0 === $dedup->find( $normalized )` — "the public deduplicator does not match a
source_not_found event". That treats the *importer's* lookup as if it were a
public query, encoding the defect as expected behaviour.

Additionally, the suite is discovered by convention but invoked with **no
argument**, so `$cli_mode` is false and **only the public phase ever runs in
CI** — the importer scenarios A/B/C were never executed by the suite runner.

## 3. The fix

### 3.1 Chosen mechanism

New production class
`wp-content/plugins/conexao-event-runtime/includes/class-conexao-event-internal-query.php`:

- `Conexao_Event_Internal_Query::run( callable )` — opens a **nesting-counted
  scope**, always closed by a `finally` block.
- `mark_query_args( array $args )` — stamps a WP_Query with
  `conexao_internal_reconciliation` = a **per-process random 32-char token**
  generated by `wp_generate_password()`.

The importer wraps its identity resolution in that scope
(`Conexao_Event_Deduplicator::find()` → `find_internal()`), and its three
lookups (`find_by_source`, `find_by_url`, `find_by_content`) go through a
single `reconciliation_query()` helper that applies the stamp.

The public filter gains **one** block, evaluated **last**, after `is_admin()`,
after the `WP_CLI` escape and after the post-type scope check.

### 3.2 Why it is fail-closed

1. The token is generated in PHP and **never derived from any request input** —
   not `$_GET`, `$_REQUEST`, a header, a cookie or a nonce. It cannot be
   predicted or supplied from outside.
2. Two conditions must **both** hold: the scope is open **and** the token
   matches. A query carrying the argument with a guessed value is gated,
   because the scope is closed.
3. Inside an open scope an **unmarked** query is still gated — the scope alone
   exempts nothing.
4. The scope closes in `finally`, so a thrown exception cannot leak an open
   scope; the depth is also clamped at `0`.
5. `filter_public_event_queries()` remains the security boundary. This only
   narrows its exemption to queries the importer itself constructed in-process.

`WP_CLI` is **not** the mechanism and was **not** widened. It remains as an
independent, pre-existing escape.

## 5. Regression tests

`test-source-not-found-reconciliation.php` — **discovered automatically** by
`run-tests.sh` (convention), so it runs in CI. **57 passed, 0 failed.**

| # | Test | Proves |
|---|---|---|
| 1 | public hiding | a plain public `WP_Query` does not return a `source_not_found` event; it is hidden by the status gate, not by `post_status` |
| 2 | importer visibility | `find()` resolves the hidden record **by `(source, source_id)` identity** |
| 3 | reappearance | upsert returns the **existing** native ID, action is **not** `created`, status restored to `published`, exactly **1** native record, source UID and canonical identity unchanged |
| 4 | repeated reappearance | 3 further hide/re-import cycles; the native-ID set stays `[14240]` every time |
| 5 | cross-source dedup | a genuinely new event matches nothing and is created **once**; re-import matches it and creates nothing |
| 6 | no leakage | homepage upcoming section, events archive, array `post_type`, filtered archive, date-specific, mixed post types, taxonomy-shaped, generic — all exclude it |
| 7 | WP-CLI independence | the suite asserts it runs with `WP_CLI` **not** defined and prints the context |
| 8 | non-forgeability | guessed argument value gated; attacker `$_GET`/`$_REQUEST` gated; scope closed outside the importer; unmarked query gated even inside the scope; marked query inside the scope is exempt; scope closed after return and after a thrown exception |

Identity is verified by **direct SQL on `(source, source_id)`** returning the
native post IDs — never by a bare "duplicates = 0" count.

## 6. Security proof

The exemption cannot be activated by an arbitrary public HTTP request:

| Attempt | Result |
|---|---|
| `?conexao_internal_reconciliation=1` as a query arg | **gated** — scope is closed |
| the same key in `$_GET` / `$_REQUEST` | **gated** — token is never read from input |
| any guessed token value | **gated** — `hash_equals` against an unguessable 32-char token |
| the importer's marked query from a request | impossible — the token is process-private and the scope is opened only by importer code |

The public filter is still the boundary, and the mark is added by the importer's
**own PHP**, never parsed from a request.

## 10. Rollback

The change is three source files and two test files, with no data migration and
no schema change.

```bash
# Revert the fix
git checkout -- \
  wp-content/plugins/conexao-event-runtime/conexao-event-runtime.php \
  wp-content/plugins/conexao-event-runtime/includes/class-conexao-event-internal-query.php \
  wp-content/plugins/conexao-event-importer/includes/class-event-deduplicator.php
rm -f wp-content/plugins/conexao-event-importer/tests/test-source-not-found-reconciliation.php
```

Reverting restores the G16 behaviour exactly (the negative control in §5.1 is
that state). **No content or database rollback is required**, because the fix
only changes what an importer query may see; it never writes, deletes or
mutates an event record.

The 243 pre-existing duplicate native IDs are **not** touched by the fix and
are **not** cleaned up here. Removing them is a separate, data-bearing change
that requires its own plan (inventory → manifest → dry-run → snapshot →
idempotent apply → verify), per engineering standard §5.2.
