**Why patch and not minor/major.** §11 mandates *that* versions are bumped in
the component header; it does not mandate an increment size. `master`→`i18n`
changed all five artifacts substantially (the audit counted 127 files,
+28,738/−6,619), but it introduced **no interface, schema, route, taxonomy or
configuration break**: no public function was removed or renamed, no meta key,
CPT, taxonomy or REST field changed shape, and no template contract moved. Every
change is additive or internal, so the next **patch** version is the honest
increment under SemVer. A minor bump would claim a new public contract that this
change does not deliver.

**Why the version *constant* was bumped with the header.** Each plugin already
ships a version constant used for **asset cache-busting**
(`wp_enqueue_*` `ver=` arguments, and `CONEXAO_THEME_VERSION` as the fallback in
`conexao_asset_version()`). Leaving the constant behind would have produced a
repository with **two disagreeing version statements per plugin** — precisely the
second source of truth AGENTS.md forbids — and would have kept serving stale
cached admin CSS/JS to exactly the maintainers this bump exists for. These are
authoritative version declarations, not code changes.

**Unchanged, deliberately.** The local-only tooling plugins
(`conexao-event-importer` 1.7.1, `conexao-leisure-migration` 2.1.0,
`conexao-sponsor-migration` 1.1.0, `conexao-translation-rollout` 1.1.0,
`conexao-en-translation` 1.5.0) and the five retired rollout plugins keep their
versions; they are not production artifacts.

**No allowlist change was needed.** `plugins.json` was **not** edited: the five
bumped artifacts were already `production: true` + `build: true`, and the
bump changes no registry fact (load order, class, status, dependencies,
production flag, build flag, mount flag are all identical).
`php scripts/generate-registry-docs.php --check` → exit 0, 14 plugins, 23
regions current.
