## 1. Scope

The G8 expansion registered 78 Eventbrite **date-window** sources —
`eventbrite_<county>_events_{today,tomorrow,this_week}`, 26 counties × 3 windows —
displayed in Event Import → Event Sources as
`Eventbrite — <County> (Today)`, `Eventbrite — <County> (Tomorrow)` and
`Eventbrite — <County> (This week)`. They are the only objects in the plugin
whose text contains those three parenthesised markers.

This change **removes those registrations from the plugin, durably**:

1. `Conexao_County_Registry` stops generating them (`EVENTBRITE_DATE_WINDOWS`,
   `get_eventbrite_window_source()` and `get_all_eventbrite_window_sources()` are
   removed; `get_all_county_sources()` keeps only the 52 county sources).
2. `Conexao_Event_Sources::get_all()` **actively strips** any registration of
   that shape that is already persisted in an environment's
   `conexao_event_sources` option — the same mechanism already used for the
   retired `laois_council` / `leo_laois` / `local_enterprise_office_laois` ids —
   so the self-healing merge can never resurrect them.
3. Tests and the canonical plugin documentation are updated to match.

The registry therefore goes from **130 county/window sources** (58 with the six
legacy defaults) to **52 county sources** (58 total).

## 2. Explicit non-goals

- **No Event content is deleted.** `_event_source` meta is bookkeeping, not
  content: the measured inventory shows **0** imported events carrying a window
  `_event_source` and **0** event titles containing the markers
  (`01-inventory-before.txt`). Events previously imported by a window source
  would be preserved, exactly as the retired-source contract already states.
- **No production write.** No `wp_options` mutation on production, no Polylang
  change, no deploy. Only the local Docker registry is exercised, and only
  through the plugin's own code path.
- **No `conexao_event_source_health` pruning.** That option holds per-source
  bookkeeping only; it is not a registry and no window entries exist locally.
- **No new architecture.** The `eventbrite` source type, the county region gate,
  identity/dedup and the G8/G9/G10 truncation/cooldown/checkpoint guards are
  untouched — the truncation guard still applies to every Eventbrite listing.
- **No rewriting of historical reports or evidence.** `docs/reports/…` and older
  `docs/evidence/…` trees stay as dated records; only the living per-plugin
  document changes.
- Not touching the Flutter/mobile repository.

## 5. Design decisions

| Decision | Reason |
|---|---|
| Delete the registry generators instead of leaving them unregistered | An unregistered-but-present generator is dead public API that a future `get_all()` merge or an experiment script could re-introduce. The registry is the single source of truth; a source that must not exist should not be generatable. |
| Retire persisted ids by **pattern**, not a hard-coded list of 78 ids | One regex derived from the same naming scheme (`^eventbrite_[a-z]+_events_(today\|tomorrow\|this_week)$`) cannot drift from the ids it retires, cannot collide with a county listing (`eventbrite_<county>`), and covers ids already written into any environment. |
| Put the retirement next to the existing retired-ids loop in `get_all()` | Same mechanism, same read path, same "never resurrects a retired source" guarantee the docs already promise. No second registry, no new admin screen, no CLI. |
| Keep the G8 truncation / G9 cooldown / G10 checkpoint guards and their tests | They are about Eventbrite listings in general, not about the window sources. Only the window-specific assertions change. |
| Bump the plugin version 1.9.0 → 1.10.0 | The registry an operator sees changes; the version is the documented release marker and its source is the plugin header. |

## 7. Safety controls

- Inventory is read-only and ran **before** any write (`00-inventory-probe.php`,
  `01-inventory-before.txt`).
- The pre-change registry option is snapshotted for rollback
  (`02-snapshot-registry-option-before.txt`); restoring it is a one-line
  `wp_options` update and is written down here.
- The retirement is **idempotent**: it only unsets ids, so a second read reports
  zero changes.
- No write happens on a page load or GET beyond the registry read path the
  plugin already uses, and no external request is sent: a retired source can
  never be enumerated, fetched or imported.
- Nothing outside the local Docker WordPress is touched; production is not
  contacted and not authorised.

## 8. Rollback

1. Restore the option: `UPDATE wp_options SET option_value = '<snapshot>' WHERE
   option_name = 'conexao_event_sources';` (snapshot in
   `02-snapshot-registry-option-before.txt`).
2. `git revert` the change set to restore the registry generators, the tests and
   the documentation.
3. Rollback restores nothing else, because nothing else changed: no event post,
   term, image or translation is created, updated or deleted.
