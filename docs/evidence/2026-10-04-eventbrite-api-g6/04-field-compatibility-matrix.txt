G6 Field-level compatibility matrix
==================================
Method: the UNMODIFIED production Conexao_Eventbrite_Normalizer was run
against an UNMODIFIED documented-shape Eventbrite v3 event object (the offline
contract fixture). The "Direct?" column states whether the existing normalizer
consumes it with no translation at all. These are MEASURED results, not
expectations — three results surprised the initial hypothesis and are recorded
as measured.
HTML-side facts below were VERIFIED against the live Cork page-1 payload on
2026-10-04, not assumed. Two findings contradict the naive reading and are
recorded as measured: the live HTML event has NO `primary_organizer` key, and
its `published` field is a publish TIMESTAMP string rather than a boolean.

MEASURED SUMMARY
----------------
No translation needed (9):      identity, title, summary, venue, address,
                               town, image, price, online/protected flags
Translation needed (10):        start_date, start_time, end_date, end_time,
                               timezone, organizer, organizer_id, published,
                               cancelled, ticket_url
Loss of fidelity / extra call(3): county-region, category label, recurrence

Of 13 importer fields measured in the offline suite, 7 are empty when a raw API
object is passed to the unchanged normalizer. All 7 are recoverable by a
key-mapping step over data the API demonstrably supplies.

ARCHITECTURAL CONSEQUENCE
------------------------
An API adapter MUST exist and MUST own exactly two things:
  1. a flat-to-nested key/rule mapping (dates, timezone, organizer, status);
  2. the region/county classification the API does not provide.
Everything downstream — Conexao_Eventbrite_Normalizer, the county registry, the
importer engine, deduplication, and the G1–G5 completeness and rate-limit
semantics — is reused UNCHANGED. Verified end-to-end in the offline suite: a
shaped adapter restores all 13 fields through the shared normalizer.
