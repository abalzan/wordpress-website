# Manual translation runbook (Stage 17)

Generated from the authoritative prerequisite registry in
`scripts/lib/commissioning.py`. Do not edit this file by hand; edit the
registry and re-render.

## Permanent AUTOMATIC translation is retired

This runbook no longer describes how to commission automatic
translation, because automatic translation no longer exists. It
describes the RETAINED manual workflow, which uses the same shared
engine (`conexao-translation-rollout`) and the same safety controls.

There is no broker, no permanent provider credential, no cron, no
webhook and no unattended execution. When English translation is
needed an operator runs it deliberately; when it is not needed,
nothing runs.

## Safety facts that gate every step

These are still checked on every run of the readiness gate and are
NOT retired:

- `P01` production_access [RETAINED] — A valid, authorized production deployment or admin channel exists and is named.
- `P02` install_authorization [RETAINED] — Explicit operator authorization to install and activate the production artifacts.
- `P03` provider_credential [RETIRED] — RETIRED as a permanent requirement (Stage 17): a manual run supplies the provider key in the environment of that run only. It is never stored in wp_options.
- `P04` provider_quota [RETIRED] — The provider account is capable of serving the required smoke test.
- `P05` live_smoke_authorization [RETIRED] — Explicit permission to make the live provider smoke request.
- `P06` provider_smoke_success [RETIRED] — A genuine live provider smoke returned RESULT: OK.
- `P07` human_reviewer [RETAINED] — A real human reviewer is identified for canary quality review.
- `P08` canary_authorization [RETIRED] — Separate explicit authorization for the canary workflow.
- `P09` apply_authorization [RETAINED] — Separate explicit authorization to mutate exactly the approved canary.
- `P10` commissioning_authorization [RETIRED] — Separate authorization to install and activate the production infrastructure itself.
- `P11` batch_control_commissioning_authorization [RETIRED] — Explicit authorization to commission the batch-control capability.
- `P12` fresh_baseline_readiness [RETAINED] — Current production state can be captured after deployment, including re-verification of the six historical PT restorations.
- `P13` legacy_endpoint_verification [RETAINED] — The legacy endpoint can be positively verified to return 410 in production.
- `P14` proof_trigger_verification [RETAINED] — The authenticated proof path can be executed end to end, ending at apply unreachable.
- `P15` emergency_stop_readiness [RETIRED] — Production is positively observed to be in the required fail-closed stopped state, and readiness does not clear it.
- `P16` audit_readiness [RETAINED] — Production audit storage and retention are available.
- `P17` release_readiness [RETAINED] — The final artifacts are verified, deterministic and free of secrets, tests and local files, with operator-chosen limits recorded.
- `P18` model_a_production_proof [RETIRED] — A real production canary demonstrates approved scope == executed scope.

## 1. Identify the PT records that need English

- a human reads the site; no automatic scope discovery exists

## 2. Request a manual translation run

- Tools -> Translation Automation; authenticated, POST-only, manage_options + nonce

## 3. Generate the inventory and manifest

- the engine builds the candidate set from the live PT inventory

## 4. Run the dry run

- MODE_PROOF only; writes nothing and reaches no apply path

## 5. Review the exact plan

- a real human reads every candidate and its scope

## 6. Approve the exact digest and scope

- digest-bound approval; a changed digest invalidates the approval

## 7. Apply explicitly

- one approved scope; approved == planned == executed

## 8. Verify

- exact mutation-set equality, PT immutability, B1/B2 policy, audit record

## 9. Reconcile for idempotence

- a second identical run changes nothing

## 10. Leave automatic execution OFF

- there is no mechanism that can turn it on

## What this runbook is not

- It is not a script. Nothing here is executed by the readiness gate.
- It does not commission anything. Automatic translation is retired, and
  `commissioning_permitted` is permanently false.
- It does not supply a provider credential. For a manually requested
  run the operator supplies the key in the environment of that run only;
  it is never written to `wp_options`, never committed and never stored
  in an artifact.
