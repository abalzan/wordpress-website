ORIGIN ANALYSIS — WHY THE TAXONOMY DEBT EXISTS (done BEFORE any change)
=====================================================================
Measured storage: Polylang 3.8.9 stores TERM language as an object-term
relationship in its internal `term_language` taxonomy, NOT in a DB column.
Every term-language count below comes from that relationship table:

  SELECT target.taxonomy, lang.slug, COUNT(*)
    FROM wp_term_relationships tr
    JOIN wp_term_taxonomy langtt ON langtt.term_taxonomy_id=tr.term_taxonomy_id
                              AND langtt.taxonomy='term_language'
    JOIN wp_terms lang ON lang.term_id=langtt.term_id
    JOIN wp_term_taxonomy target ON target.term_id=tr.object_id
   WHERE target.taxonomy IN ('conexao_county','conexao_town','conexao_category','conexao_tag')
   GROUP BY target.taxonomy, lang.slug;

  conexao_category  pll_pt  58
  conexao_category  pll_en  16
  conexao_county    pll_pt  32
  conexao_town      pll_pt 250

This EXACTLY accounts for the 32 + 250 = 282 taxonomy gate violations, and
proves the translated category/tag terms are unaffected (58 PT / 16 EN).

Origin, proven rather than assumed:

1. NO CURRENT CODE CREATES THE TAGS. `conexao_polylang_translated_taxonomies()`
   (theme inc/i18n/guard.php) declares ONLY conexao_category and conexao_tag
   as Polylang-translated. conexao_county and conexao_town are declared shared.

2. THE SEED IS ALREADY CORRECT. `Conexao_Data_Model_Relationships::seed_terms()`
   (wp-content/plugins/conexao-data-model/includes/class-relationships.php)
   uses a bare `wp_insert_term( $term, 'conexao_county' )`. Because the
   taxonomy is no longer translated, that call no longer assigns a language.

3. PROVEN EMPIRICALLY: inserting a throwaway term `ZZ StageM Probe County`
   into conexao_county at the Stage M start SHA returned lang=false (NO
   language), and the probe term was deleted immediately. A freshly seeded
   county/town term is ALREADY language-neutral.

CONCLUSION: the 282 language tags are HISTORICAL RESIDUE from the period
before the Stage 3.2 policy correction, when county/town WERE Polylang
translated and Polylang tagged them on insert. Nothing in the current
repository regenerates them, so the SOURCE of this debt is already correct and
must not be changed. The remediation is a data cleanup that removes the stale
`term_language` relationships. There is no seed/import defect to repair.
