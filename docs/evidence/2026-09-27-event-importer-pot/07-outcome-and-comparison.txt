== ONE TRANSLATOR-COMMENT DIFFERENCE (documented, not repaired) ==
Lost: "#. translators: %d: number of parts generated before the failure"
  (1 of 85 extracted comments; tracked 85 -> generated 81)
Cause: the comment sits INSIDE a sprintf( argument list, one line above a
MULTI-LINE _n( call. Proven with minimal reproductions: xgettext associates a
translators comment with a gettext call only when the call is on ONE line
  single-line _n  -> comment IS extracted
  multi-line _n   -> comment is NOT extracted
This is stock xgettext 0.23.2 behaviour with the generator's documented
--add-comments=translators, not a defect introduced by this task, and not
specific to this component. The plugin SOURCE is correct and the msgid is
fully preserved. Repairing it would mean editing PHP source or hand-editing
the POT, both of which this task forbids. Recorded as a limitation.
