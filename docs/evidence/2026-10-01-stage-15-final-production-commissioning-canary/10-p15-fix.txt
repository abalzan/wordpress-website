STAGE 15 ADDENDUM - THE P15 FIX

## The defect

P15 `emergency_stop_readiness` was declared `evidence_source=REPOSITORY_ARTIFOT`
with `evidence_type=None`, AND its validator additionally demanded a repo
fact `production_stop_state_observed` that the preflight hardcoded to False:

  scripts/verify-commissioning-readiness.py:336 (before)
    "production_stop_state_observed": False,

  scripts/lib/commissioning.py:925 (before)
    if not repo.get("production_stop_state_observed"):
        return _blocked(...)

The conjunction of "no evidence type" AND "a hardcoded False repo fact" made
P15 unsatisfiable by ANY operator evidence. The aggregate could never
reach READY. Proven empirically, not assumed: with a COMPLETE evidence
set of all 15 objects plus a credential, 17 of 18 prerequisites reached
READY and P15 alone stayed BLOCKED.

## The fix

P15 is now `LIVE_PRODUCTION_READ` / `production_stop_state` / `FRESH_PRODUCTION_READ`,
matching the neighbouring production reads (P12/P13/P14/P16). The fact
being checked is a fact about PRODUCTION, so it is carried by production
evidence. The artifact-side fail-closed check remains a REQUIRED
repository fact inside the validator, so BOTH halves are proven.

This is STRICTER than the code it replaces:
  - both halves required (artifact fails closed AND production stopped)
  - production-grade provenance REQUIRED; local/artifact proofs are refused
  - only a POSITIVE STOPPED accepted; absent/false/malformed -> BLOCKED
  - a self-contradictory object (STOPPED beside stopped=false) -> BLOCKED
  - freshness applies; a stale production read goes EXPIRED

UNCHANGED and still asserted: readiness NEVER clears the stop.
emergency_stop_clearance stays NOT_GRANTED, emergency_stop_clears stays 0.
