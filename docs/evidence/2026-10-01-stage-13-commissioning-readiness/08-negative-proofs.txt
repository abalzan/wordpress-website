## The positive control comes FIRST

The fully-evidenced control environment is asserted to reach READY with
commissioning_permitted = true BEFORE any negative is injected. A proof that
passes because the baseline is already red proves nothing, so the baseline is
proven green first.

## Secret-boundary negatives

  assert_no_secrets() REFUSES each of: a provider key (sk-...), a WordPress
  application password (4x4 word shape), a nonce, a cookie, an Authorization
  header, a PEM private key, and any secret-NAMED key.

  The Python boundary is deliberately STRICTER than the PHP mirror, which
  recognises only the 4x4 word shape and would pass an sk- key, a PEM block or
  an Authorization value. That PHP gap is recorded as Stage 14 work rather than
  fixed here: tightening shipped plugin code mid-stage would change the very
  release artifacts this stage is verifying.

  The boundary also caught THREE genuine mistakes in the readiness report's own
  key names during development ("authorizations", "provider.credential_present",
  "site.is_authorization"), which is the evidence that it runs on the way OUT.
