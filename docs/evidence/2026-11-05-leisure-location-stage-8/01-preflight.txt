Migrate the Lazer location dataset (coordinates, and optionally the practical-attribute taxonomy) to a WordPress target over the REST API. Dry run by default.

options:
  -h, --help            show this help message and exit
  --target-url TARGET_URL
                        The WordPress site to migrate INTO (e.g. the
                        production site). REQUIRED for --apply and --verify;
                        there is deliberately no default.
  --source-url SOURCE_URL
                        Optional local site to READ attribute taxonomy from.
                        Defaults to the manifest only (coordinates need no
                        live source).
  --manifest MANIFEST   Reviewed coordinate manifest (default:
                        scripts/data/leisure-coordinates-2026-11-03.json).
  --include-attributes  Also ADD missing conexao_leisure_attribute terms,
                        resolved by slug. Add-only; target terms are never
                        removed and never created.
  --overwrite           Allow an existing DIFFERING target coordinate to be
                        replaced. Off by default.
  --state-file STATE_FILE
                        Resume journal path (default: .local/leisure-location-
                        migration-state.json).
  --no-resume           Ignore the resume journal and consider every record
                        fresh.
  --request-delay REQUEST_DELAY
                        Seconds to wait between writes (default 0.25; protects
                        the rate limit).
  --report REPORT       Write the machine-readable JSON report to this path
                        (never contains credentials).
  --confirm-production  Acknowledge a write against a production target.
                        Required for a production --apply.
  --apply               Perform the plan (writes).
  --dry-run             Plan only (the default).
  --verify              Read-only coverage report.

Safety
  * Dry run is the DEFAULT and writes nothing. --apply is the only write mode.
  * --target-url has no default: the target is always named explicitly, and a
    production target additionally requires --confirm-production.
  * Credentials come from WP_USERNAME / WP_APPLICATION_PASSWORD only. They are
    never printed, logged, or written into the report.
  * Records are matched by SLUG, never by local post ID (IDs are not portable).
  * Additive only: an existing differing target coordinate is reported as a
    CONFLICT and skipped unless --overwrite is given. Nothing is deleted, no
    record is created, no status, title, taxonomy (other than the opt-in
    attribute taxonomy) or translation relationship is touched.
  * Rate-limit aware: HTTP 429 is honoured via Retry-After with bounded backoff.
  * Resumable: applied records are journaled, so an interrupted run continues.

Modes
  --dry-run             (default) print the plan and write nothing.
  --apply               perform the plan. Requires --target-url (and
                        --confirm-production when the target is production).
  --verify              read-only: report target coverage and exit.
  --help                print this message and exit 0.
